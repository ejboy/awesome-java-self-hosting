# Contributing

Submissions are welcome when a resource has a concrete reason to be recommended for people running their own Java or JVM applications.

The inclusion test is: **Does this materially help somebody deploy, operate, secure, monitor, back up, or troubleshoot a Java/JVM application they run themselves?**

Resources that reduce operational complexity, solve a production problem well, improve reliability, or explain a practical deployment are especially useful. Small-server relevance is welcome, but not a strict requirement. Official documentation is preferred when it answers the question well.

Self-submissions are welcome. Please disclose whether you are the author, maintainer, employee, sponsor, or otherwise affiliated with the resource. Inclusion is editorial and the list is intentionally not exhaustive; absence is not a negative judgment. Maintained and usable projects are preferred, and there are no arbitrary GitHub-star requirements.

When proposing a resource, include its canonical URL and a concise explanation of the operational problem it solves. Check that the link works and that the project or material is current enough to recommend.

Pull requests must be authored by the person submitting them. Do not list AI tools (such as Claude, ChatGPT, or Copilot) as co-authors or add AI `Co-Authored-By` trailers. Pull requests with AI tools credited as co-authors will be rejected; you are the author and are responsible for your submission.
